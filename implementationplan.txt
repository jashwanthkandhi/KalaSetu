# KalaSetu MVP — Implementation Plan

> **Stack:** SIH26090 Final · **Source docs:** research + PRD + TechDesign (updated) + README
> **Tagline:** From Voice and Vision to Marketplace in Seconds
> **Platform:** Flutter (Android) · **Timeline:** 48-hour SIH MVP

---

## What We Are Building

```
Artisan opens app → selects language → takes photo → speaks in Telugu/Hindi
                          ↓
         (offline? → Hive queue → uploads when signal returns)
                          ↓
Backend: Whisper STT → Qwen-Image-Edit (NVIDIA NIM) → MobileNetV3 category → Nemotron listing → SerpApi price
                          ↓
Artisan reviews & edits AI-generated card → confirms → saved to Supabase catalog
```

Everything outside this flow is out of scope for the 48-hour MVP (no marketplace, no payments, no ONDC, no n8n automation).

## UI/UX Visual Design Specification

> **Purpose:** This section defines how KalaSetu should look, feel, and behave visually. It does not change any functionality, backend architecture, AI pipeline, or tech stack decisions. The attached reference image is the visual benchmark for QUALITY and DESIGN DIRECTION only — not a source of screens or features.
>
> **Design philosophy:** *"Your craft deserves a bigger world."* Technology stays invisible. The artisan stays in control. Every screen must feel like part of one cohesive, professional product — not a college CRUD app or a basic Flutter demo.

---

### 1. Overall Design Direction

KalaSetu must feel like a **premium, production-quality mobile application** — comparable in visual polish to a professionally designed modern marketplace app.

**What it must feel like:**
- Warm, trustworthy, artisan-focused
- Minimal — only what is necessary
- Modern — clean, spacious, confident
- Accessible — large targets, readable text, Indic fonts rendered correctly

**What it must NOT feel like:**
- A basic Flutter prototype
- A college CRUD application
- A generic admin dashboard
- An AI developer tool
- A collection of unrelated screens

Every screen must share the same palette, spacing, typography, and component language. Consistency is non-negotiable.

---

### 2. Visual Identity

#### Color Palette

| Token | Hex | Role |
|---|---|---|
| `colorBackground` | `#F5F0EB` | Warm cream — all screen backgrounds, never white |
| `colorSurface` | `#FFFFFF` | White — cards, input fields, bottom nav bar |
| `colorPrimary` | `#C4622D` | Terracotta — primary buttons, active states, mic button, waveform, active nav |
| `colorSecondary` | `#D4A017` | Saffron/gold — AI suggested price, star accents |
| `colorText` | `#2C1810` | Deep brown/charcoal — all headings and primary body text |
| `colorTextMuted` | `#8A7A70` | Warm gray — secondary labels, hints, timestamps, helper text |
| `colorSuccess` | `#4CAF50` | Soft green — Saved chip, completed processing step, save confirmation |
| `colorWarning` | `#F59E0B` | Amber — Draft chip, offline queue badge |
| `colorError` | `#D32F2F` | Muted red — error messages, failed states |
| `colorBanner` | `#FFF3E0` | Saffron-tint — AI review banner background |
| `colorBorder` | `#E8DDD5` | Warm light brown — card dividers, chip outlines, unselected language pills |
| `colorOverlay` | `#2C181066` | Semi-transparent deep brown — image overlays, modal backdrops |

**Rules:**
- Never use pure black or pure white for text
- Maximum 3 colors visible on any single screen at once
- No excessive gradients — flat fills only, exception: very subtle cream-to-transparent hero fade on onboarding
- Green is reserved exclusively for success/positive states
- Red is reserved exclusively for error states

### 3. Typography

**Font:** Noto Sans (bundled in assets) — covers Latin, Devanagari (Hindi), and Telugu scripts in one family. Do not mix font families.

#### Type Scale

| Style name | Size | Weight | Line height | Usage |
|---|---|---|---|---|
| `displayL` | 34sp | Bold (700) | 1.15 | Onboarding headline |
| `headingL` | 24sp | Bold (700) | 1.2 | Screen titles (My Catalog) |
| `headingM` | 20sp | SemiBold (600) | 1.25 | Card titles, listing title in Review |
| `headingS` | 17sp | SemiBold (600) | 1.3 | Section labels, nav bar title |
| `bodyL` | 15sp | Regular (400) | 1.5 | Descriptions, body copy |
| `bodyM` | 13sp | Regular (400) | 1.5 | Secondary copy, hints, timestamps |
| `label` | 11sp | Medium (500) | 1.3 | Status chips, tags, category pills |
| `price` | 22sp | Bold (700) | 1.0 | Price values (INR) |
| `priceMuted` | 16sp | Regular (400) | 1.0 | AI Suggested price label |
| `button` | 16sp | SemiBold (600) | 1.0 | Primary/secondary button labels |
| `micro` | 11sp | Regular (400) | 1.4 | Sub-button hints, footnotes |

**Indic rendering rules:**
- `NotoSansTelugu-Regular.ttf` and `NotoSansTelugu-Bold.ttf` bundled for Telugu
- `NotoSansDevanagari-Regular.ttf` and `NotoSansDevanagari-Bold.ttf` bundled for Hindi
- Language selector pills must use the correct script for each language (`తెలుగు`, `हिंदी`, `English`)
- Never render Indic text with a Latin-only font — it will show squares

### 4. Layout

#### Spacing System

Base unit: **4dp**

| Token | Value | Usage |
|---|---|---|
| `space4` | 4dp | Icon-to-label gap, chip internal padding |
| `space8` | 8dp | Between small elements within a card |
| `space12` | 12dp | Card grid gap, chip row gap |
| `space16` | 16dp | Standard internal card padding, section gap |
| `space20` | 20dp | Card-to-card vertical gap |
| `space24` | 24dp | Screen horizontal padding (left + right) |
| `space32` | 32dp | Between major sections |
| `space48` | 48dp | Large section breaks |

**Screen padding:** 24dp left and right on all screens. No full-bleed content except images and the onboarding hero visual.

#### Border Radius

| Element | Radius |
|---|---|
| Cards (large) | 16dp |
| Cards (small) | 12dp |
| Primary button | 14dp |
| Secondary button | 14dp |
| Chips / pills | 100dp (fully rounded) |
| Input fields | 10dp |
| Image containers | 16dp |
| Banners / alerts | 10dp |
| Bottom nav bar | 0dp (flush to screen edge) |

#### Elevation (Shadows)

Use shadow instead of borders to separate cards from the cream background.

```
Card shadow:   blurRadius=12, offset=(0,4), color=#2C1810 at 6% opacity
Sticky bottom: blurRadius=16, offset=(0,-4), color=#2C1810 at 8% opacity
```

No Material elevation values — use explicit `BoxShadow` definitions.

### 5. Reusable Components

Every component below must be implemented as a separate Flutter widget in `lib/shared/widgets/`. No duplicating layout logic inline across screens.

#### `PrimaryButton`
- Height: 56dp, full-width with 24dp horizontal screen padding
- Background: `colorPrimary` (#C4622D), border radius 14dp
- Label: `button` type style, white
- Press feedback: `AnimatedScale` to 0.97, 100ms `Curves.easeOut`
- Disabled state: 40% opacity, no press feedback
- Loading state: replaces label with 20dp white `CircularProgressIndicator`

#### `SecondaryButton`
- Height: 48dp, full-width
- Background: transparent, border: 1.5dp `colorPrimary`, border radius 14dp
- Label: `button` type style, `colorPrimary`
- Use for: Re-record, Retry, secondary actions

#### `AppHeader`
- Back arrow (line icon, `colorText`, 48dp tap target) — left
- Screen title (`headingS`, `colorText`) — center
- Optional trailing widget (badge, icon button) — right
- Background: `colorBackground` (same as screen — no elevation)
- Consistent 56dp height

#### `LanguageSelector`
- Three pill buttons: `తెలుగు` | `हिंदी` | `English`
- Selected: `colorPrimary` fill, white label text, 0dp border
- Unselected: `colorSurface` fill, `colorBorder` 1dp border, `colorTextMuted` label
- Pill height: 40dp, border radius 100dp
- Tap: `AnimatedContainer` color switch, 150ms
- Persisted to `SharedPreferences`

#### `ProductCard`
- White surface, 16dp border radius, card shadow
- Square image top: `AspectRatio(1:1)`, `CachedNetworkImage`, `BoxFit.cover`, 16dp radius top corners only
- Content padding: 10dp all sides
- Title: `bodyL` bold, `colorText`, max 2 lines, overflow ellipsis
- Category: `bodyM`, `colorTextMuted`, 1 line
- Price row: `price` style `colorText` left + `StatusChip` right, vertically centered

#### `StatusChip`
- Height: 22dp, padding: 6dp horizontal, border radius 100dp
- Saved: `colorSuccess` border (1dp) + text
- Draft: `colorWarning` border + text
- Pending Upload: `colorWarning` fill at 20% + `colorWarning` text + wifi-off icon 12dp
- Queued: `colorPrimary` border + "Queued" text + upload icon 12dp
- Label: `label` type style

#### `ProgressStep`
- Row: 56dp height, 20dp horizontal padding, thin `colorBorder` divider below (except last)
- Left icon 32dp circle:
  - Completed → filled `colorSuccess`, white checkmark
  - Active → filled `colorPrimary`, white animated spinner
  - Pending → outlined `colorBorder`, no fill
- Center: step label `bodyL`, `colorText` bold when active, `colorTextMuted` when done/pending
- Right: animated `...` dots in `colorPrimary` when active, nothing otherwise

#### `LoadingIndicator`
- Three dots, 8dp diameter each, 6dp gap
- Color: `colorPrimary`
- Animation: sequential opacity pulse, 400ms each, offset 133ms between dots

#### `EmptyState`
- Centered column
- Illustration: simple line-art craft icon (SVG), 120dp, `colorBorder` tint
- Title: `headingM`, `colorText`
- Body: `bodyM`, `colorTextMuted`, centered, max 2 lines
- Optional CTA: `PrimaryButton`
- Example — empty catalog: "Your catalog is empty" / "Create your first listing and start selling." / [Create Listing]

#### `ErrorState`
- Centered column
- Icon: exclamation in circle, `colorError` tint, 64dp
- Title: `headingS`, `colorText` — artisan-friendly, never expose technical errors
- Body: `bodyM`, `colorTextMuted`
- `RetryButton` below

#### `RetryButton`
- `SecondaryButton` variant, label "Try Again", arrow-rotate icon left
- Always visible when an error has occurred — never leave user stuck

#### `VoiceRecorderButton`
- Circular, 96dp diameter, `colorPrimary` fill, white mic icon 40dp
- Idle state: solid circle, no rings
- Recording state: 3 concentric rings — `colorPrimary` at 15%, 10%, 5% opacity, radii 60/72/84dp — animated `RepeatAnimation` pulse, 1200ms
- Stop state: square stop icon replaces mic, same circle

#### `ImagePreviewCard`
- White card, 16dp radius, card shadow
- Image: `CachedNetworkImage`, `BoxFit.cover`, 4:3 aspect ratio for review / 1:1 for capture zone
- Placeholder: cream background + camera icon `colorBorder` centered
- Error fallback: cream background + broken image icon + "Couldn't load image" `bodyM`
- Optional "Edit" pill overlay: top-right, white surface, pencil icon + "Edit" label, 28dp height

#### `PriceBadge`
- AI suggested: `colorSecondary` (#D4A017) text, `priceMuted` label above
- Editable (Your Price): `TextFormField` with terracotta underline, `price` type style, `colorText`
- INR symbol: always prefix `₹` before the value, non-editable

#### `TagChip`
- Outlined pill, `colorBorder` 1dp border, `colorText` label, `label` type style
- Padding: 8dp horizontal, 4dp vertical, border radius 100dp
- Tap to edit: opens bottom sheet text input

#### `BottomActionBar`
- Fixed bottom, white surface, top shadow (see elevation spec)
- Contains: `PrimaryButton` + optional microtext below button
- Height: 96dp (button + padding + safe area inset)
- Safe area aware (`SafeArea`)

### 8. Processing Screen

**Goal:** Visually impressive wait experience. Artisan must feel something real is happening.

**Layout:**
- No `AppHeader`, no back button — screen is non-dismissible during active processing
- `KalaSetu` wordmark: centered, top, `headingM`
- `ImagePreviewCard`: full-width, shows the captured product photo as AI works on it. Below the image inside the card: `"Creating your listing..."` italic `bodyM` `colorTextMuted`
- Spacer: 28dp
- Progress card: white card, card shadow, 4 × `ProgressStep` rows
  1. Understanding your voice
  2. Enhancing your product photo
  3. Identifying your craft
  4. Creating your listing
- `LoadingIndicator` (3-dot pulse): centered below card, `colorPrimary`
- "This usually takes about 20 seconds" — `bodyM`, `colorTextMuted`, centered

**States:**
- **Normal:** steps animate through sequentially
- **Failed:** progress card replaced by `ErrorState` — artisan-friendly message + `RetryButton` that navigates back to Capture
- No fake percentage bars — only the 4 defined stages, each either pending / active / done

### 11. Navigation

**Primary user flow (linear):**
```
Onboarding → Capture → Processing → Review & Edit → Catalog
```

**Return flows:**
- Processing failure → back to Capture (retry)
- Review → back to Capture (re-do)
- Save success → forward to Catalog (never back-stack to Review)

**Bottom nav** (visible on Capture and Catalog only — 2 tabs total):
- Capture tab
- Catalog tab
- **No Settings tab** — language selection is handled by the `LanguageSelector` on the Capture screen (persisted via `SharedPreferences`). Tutorial replay is P1/deferred.
- Bottom nav NOT shown on: Onboarding, Processing, Review

**Navigation rules:**
- No drawer, no hamburger menu
- No more than 2 levels of navigation depth
- Back arrow always visible unless on Onboarding or Processing (non-dismissible)
- `go_router` manages all routing — no direct `Navigator.push` calls

### 12. Interaction States

Every interactive element and every data-loading scenario must have a defined visual state. No screen may be left in an undefined or blank state.

| State | Visual treatment |
|---|---|
| **Loading** | `LoadingIndicator` (3-dot pulse) centered on `colorBackground`, or inline spinner inside button |
| **Success** | `ScaleTransition` green checkmark overlay, 400ms, then auto-navigate |
| **Error** | `ErrorState` widget with artisan-friendly message + `RetryButton` |
| **Retry** | `RetryButton` always visible after error — never leave user stuck |
| **Empty** | `EmptyState` widget — never show a blank white/cream screen |
| **Offline** | Amber banner on Capture, "Pending Upload" chip on catalog cards |
| **Queued** | `StatusChip` "Queued" on catalog card while in Hive queue |
| **Uploading** | `StatusChip` "Uploading..." + mini `CircularProgressIndicator` |
| **Saved** | `StatusChip` "Saved" green, plus success animation on save |
| **Disabled** | 40% opacity on button, no tap feedback |
| **Validation error** | Red underline on input + `bodyM` `colorError` inline message below field |

**Duplicate submission prevention:** "Generate Listing" and "Save Listing" buttons must be set to disabled + loading state immediately on first tap. Do not allow double-submission.

### 13. Animations

All animations must use `Curves.easeOut`. No spring physics. Keep animations lightweight and performant on mid-range Android devices (Snapdragon 400-series).

| Animation | Trigger | Widget | Duration |
|---|---|---|---|
| Screen enter | Route push | `FadeTransition` + `SlideTransition` (20dp up) | 250ms |
| Button press | Tap down | `AnimatedScale` to 0.97 | 100ms |
| Mic ring pulse | Recording active | `AnimationController` repeat, opacity 0.15→0.05 | 1200ms |
| Voice waveform bars | Recording active | `AnimationController` + `sin()` phase offset per bar | 60fps |
| Processing step done | Step completes | `AnimatedContainer` fill + `FadeIn` checkmark | 300ms |
| Success save | Save confirmed | `ScaleTransition` + green overlay | 400ms |
| Catalog card entrance | Grid build | Staggered `FadeTransition` + `SlideTransition`, 50ms offset | 200ms |
| Image crossfade (Review) | Original ↔ Enhanced toggle | `AnimatedCrossFade` | 300ms |
| Language selector switch | Pill tap | `AnimatedContainer` color | 150ms |

**Rules:**
- No Lottie files for core UI — only for onboarding illustration (one-time, small file)
- Never block user interaction with an animation
- Reduce animations if `MediaQuery.disableAnimations` is true

---

### 14. Error UX

Users must never see technical errors. Every backend failure must be mapped to a simple, artisan-friendly message.

| Backend / system error | User-facing message |
|---|---|
| STT failed (Whisper + GCloud both fail) | "We couldn't understand the recording. Please try speaking again." |
| Image enhancement failed (Qwen) | "Photo enhancement didn't work. Your original photo will be used." (soft warning — not blocking) |
| Category tagging failed | Silent — LLM infers from transcript, no user message needed |
| LLM listing generation failed | "Listing couldn't be created. Please try again." |
| SerpApi pricing failed | Silent — cost-plus fallback used, no user message |
| Supabase save failed | "Listing couldn't be saved. Please try again." + `RetryButton` |
| No network | "You're offline. Your listing will upload when you're back online." |
| File too large | "Your photo is a bit large. We'll compress it before uploading." |
| Timeout | "This is taking longer than usual. Please try again." |

**Rules:**
- Never show stack traces, HTTP codes, API error messages, or Python errors
- Never use the word "error" alone — always add context + next action
- Always offer a recovery action (retry, re-record, go back)

### 15. Accessibility

| Requirement | Spec |
|---|---|
| Minimum touch target | 48dp × 48dp for all interactive elements |
| Font sizes | Minimum 11sp, scale with system font size (`textScaleFactor`) |
| Contrast | All text on backgrounds meets WCAG AA (4.5:1 for body, 3:1 for large) |
| Icon labels | Every icon has a text label or `Semantics(label:)` for screen readers |
| Color-only communication | Never use color as the only indicator — always pair with icon or text |
| Indic fonts | Noto Sans Telugu and Devanagari bundled — no fallback to system fonts |
| Screen sizes | Tested on 5.0", 6.0", 6.7" screens — no overflow, no clipped text |
| Tap spacing | Adjacent buttons separated by minimum 8dp |
| Error messages | Inline, below the relevant field, not as a toast that disappears |

---

### 16. Performance

| Requirement | Spec |
|---|---|
| Image loading | `CachedNetworkImage` everywhere — no raw `Image.network` |
| Image compression | Compress before upload: max 1200px long edge, JPEG 85% quality |
| Animations | Use `RepaintBoundary` to isolate animated widgets |
| Rebuild scope | Use `Consumer` / `ref.watch` on smallest possible widget subtree |
| API operations | Always show `LoadingIndicator` — never leave screen unresponsive |
| Offline list | Hive box reads are synchronous — no async gap on catalog load |
| Waveform | `CustomPainter` only — no `ListView` of animated containers |
| Font assets | Preload Noto Sans variants in `pubspec.yaml` — no FOUT (flash of unstyled text) |

### Component 1 — Supabase Data Layer






#### [NEW] `supabase/schema.sql`

```sql
CREATE TABLE artisans (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT,
    phone TEXT UNIQUE,
    preferred_language TEXT DEFAULT 'te',
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE products (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    artisan_id UUID REFERENCES artisans(id) ON DELETE SET NULL,
    title TEXT NOT NULL,
    description TEXT NOT NULL,
    category TEXT NOT NULL,
    tags TEXT[] DEFAULT '{}',
    original_image_url TEXT,
    enhanced_image_url TEXT,
    voice_transcript TEXT,
    suggested_price NUMERIC(10,2),
    final_price NUMERIC(10,2),
    status TEXT DEFAULT 'draft',
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

**Manual steps:**
1. Run schema in Supabase SQL editor
2. Create Storage bucket `listing-images` (public read for images, write restricted to backend)
3. **Enable RLS on `products` — mandatory, even for demo mode** (see TH-9 for required policies)

**One-time setup steps (before first Flutter build):**

### Component 5 — Error Handling Matrix

> Source: TechDesign §9 + PRD §7 acceptance criteria

| Failure | Backend response | Flutter behaviour |
|---|---|---|
| Whisper STT fails | Try Google Cloud STT fallback | If both fail: `transcription: null` → show "Re-record" prompt |
| Google Cloud STT fails | `success: false, error: "stt_failed"` | "Could not understand audio, try again" + keep photo |
| Qwen image enhancement fails | Return original image + `image_warning: true` | Soft warning banner; keep workflow alive |
| MobileNet category fails | `category: "Other"` | LLM infers from transcript; artisan can edit in Review |
| LLM malformed JSON | Retry once; if still bad → 500 | "Listing generation failed" + retry CTA |
| SerpApi unavailable | Cost-plus fallback price | No user-visible error; fallback is transparent |
| Supabase save fails | 503 | "Save failed — tap to retry" persistent CTA |
| No network at capture | N/A | Hive queue; "Queued for upload" badge |
| File too large | 413 + guidance message | "Image too large — we'll compress it" auto-compress |

## TH-2. NVIDIA NIM / Nemotron — Exact Configuration

### SDK — Correct Package

Use the `openai` Python package pointed at the NIM base URL. **`nvidia-nemotron` is not a real PyPI package — remove it.**

```python
from openai import OpenAI

client = OpenAI(
    base_url=settings.NVIDIA_NIM_BASE_URL,   # https://integrate.api.nvidia.com/v1
    api_key=settings.NVIDIA_NIM_API_KEY,
)
```

### Model ID

> [!CAUTION]
> **The implementation agent must verify the exact model ID before writing any code.**
> Log in to [https://build.nvidia.com](https://build.nvidia.com) with the user's NVIDIA account. Confirm which Nemotron model is available. Set `NEMOTRON_MODEL` in `.env` to the verified ID. **Never hardcode the model name in source** — always read from `settings.NEMOTRON_MODEL`.

### Request

```python
response = client.chat.completions.create(
    model=settings.NEMOTRON_MODEL,
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": f"Transcript: {transcript}\nCategory hint: {category}"},
    ],
    temperature=0.3,
    max_tokens=512,
    timeout=20,
)
```

### System Prompt (production-locked)

```
You are KalaSetu, an AI catalog assistant for Indian artisans.
Convert the artisan's spoken description into a professional English product listing.
Return ONLY a valid JSON object with these exact keys:
{
  "title": "string (max 80 chars)",
  "description": "string (max 400 chars)",
  "category": "one of: Pottery, Textiles, Bamboo, Wood, Jewellery, Paintings, Leather, Other",
  "tags": ["string"],
  "suggested_price": number
}
Rules: suggested_price MUST be a number (not a string), INR value 50–50000.
Do not invent details not in the transcript. No markdown outside the JSON.
```

### Response Validation (Pydantic)

```python
from pydantic import BaseModel, validator

class ListingSchema(BaseModel):
    title: str
    description: str
    category: str
    tags: list[str]
    suggested_price: float   # must be numeric — never str

    @validator("suggested_price")
    def price_in_range(cls, v):
        assert 50 <= v <= 50000
        return v
```

### Retry Policy

1. Parse + validate. If valid → return.
2. If invalid → retry once (15 s timeout), appending: `"Return ONLY the JSON object. No other text."`
3. If retry also invalid → `LLMGenerationError` → `error.code = "llm_failed"`.

## TH-2b. Qwen Image Enhancement — Exact Configuration

**Provider:** NVIDIA NIM
**Model:** Qwen-Image-Edit (exact ID verified from [build.nvidia.com](https://build.nvidia.com) before coding, stored in `QWEN_IMAGE_MODEL`)
**Auth:** `NVIDIA_NIM_API_KEY` + `NVIDIA_NIM_BASE_URL` — same credentials as Nemotron. No separate image API key.

> [!CAUTION]
> **Qwen-Image-Edit is a dedicated image-editing model — not a VLM chat model.**
> It does NOT use the `chat.completions` endpoint. The implementation agent MUST:
> 1. Verify the exact `QWEN_IMAGE_MODEL` ID from the NVIDIA NIM console.
> 2. Read the model's API documentation at [build.nvidia.com](https://build.nvidia.com) to confirm the correct request format (endpoint path, payload structure, and response format) for image editing.
> 3. Use that verified request format in `image_service.py`.
> Do NOT assume it uses the same endpoint as the LLM.

### Required Behavior

**Input:**
- Product image (JPEG or PNG)
- Compressed to ≤ 5 MB, max 1920px on longest edge before sending

**Edit instruction to model:**
- Remove or replace any distracting background
- Place the product on a clean white or light neutral background
- Improve lighting to clearly reveal product details and texture
- Preserve the actual product appearance — do not invent or modify the product itself

**Output:**
- Enhanced image bytes/file returned by the API
- Compress if necessary (JPEG 85%, max 1920px)
- Upload enhanced image to Supabase Storage: `listing-images/enhanced/<uuid>.jpg`
- Return public Supabase URL as `enhanced_image_url`

### Implementation Note

The implementation skeleton below is a **placeholder only**. The actual request format, endpoint, and response parsing depend on the specific NVIDIA NIM Qwen-Image-Edit API contract, which must be read from the model's documentation before writing code:

```python
import httpx

async def enhance_image(image_bytes: bytes) -> str:
    """
    Calls NVIDIA NIM Qwen-Image-Edit API.
    Implementation agent: read the exact API contract from build.nvidia.com
    for the verified QWEN_IMAGE_MODEL before implementing this function.
    """
    # 1. Compress image if > 5 MB or > 1920px
    compressed = compress_image(image_bytes, max_mb=5, max_px=1920)

    # 2. Call NVIDIA NIM Qwen-Image-Edit endpoint
    #    (use the request format documented for settings.QWEN_IMAGE_MODEL at build.nvidia.com)
    #    Instruction: remove background, clean white background, improve lighting,
    #    preserve product details, do not modify the product.

    # 3. Extract enhanced image bytes from API response
    #    (format depends on API contract — may be base64, URL, or binary)

    # 4. Upload to Supabase Storage
    path = f"listing-images/enhanced/{uuid4()}.jpg"
    supabase.storage.from_("listing-images").upload(path, enhanced_bytes)
    return supabase.storage.from_("listing-images").get_public_url(path)
```

### Constraints

| Constraint | Value |
|---|---|
| Max image size before API call | 5 MB (compress: JPEG 85%, max 1920px) |
| Accepted input MIME types | `image/jpeg`, `image/png` |
| Timeout | 25 s, 0 retries |
| Max retries | 0 (image enhancement is non-critical) |

### Fallback (mandatory)

If any exception occurs (timeout, API error, invalid response, parse error):
- Log warning with `request_id` and error type
- Return `original_image_url` (already uploaded to Supabase at start of pipeline)
- Set `image_warning: true` in the pipeline response
- **Never raise the exception to the pipeline orchestrator**
- Pipeline continues to category, LLM, and pricing normally

## TH-9. Supabase Security Model

| Credential | Used by | Rule |
|---|---|---|
| `SUPABASE_KEY` (anon) | FastAPI backend | CRUD via service logic |
| Service-role key | **Never in Flutter** | Prohibited — bypasses RLS |
| Supabase anon key | Flutter client | Read catalog listings only |

> [!IMPORTANT]
> **RLS is mandatory — not optional, even in demo mode.** The Supabase `products` table must have RLS enabled before any data is written. Use the policies below as the minimum baseline.

```sql
ALTER TABLE products ENABLE ROW LEVEL SECURITY;
CREATE POLICY "demo_read_all" ON products FOR SELECT USING (true);
CREATE POLICY "demo_insert"   ON products FOR INSERT WITH CHECK (true);
```

**Storage:** Bucket `listing-images` is public-read (product images are intentionally public). Uploads are performed **only** by the FastAPI backend using `SUPABASE_KEY`. Flutter must not have write access to storage.

**Flutter credential rule:** Flutter may use only the Supabase anon key for permitted reads (catalog listings). The service-role key must never be placed in any Flutter file, asset, or environment.

## TH-12. Offline Queue State Machine

```
[Capture, no internet] → QUEUED (Hive)
                              │
                     connectivity restored
                              ▼
                          UPLOADING
                         ╱         ╲
                   success         failure
                      │                │
                   SUCCESS          FAILED (retry_count++)
                                    │
                              if count < 3 → back to QUEUED
                              if count >= 3 → DEAD (surface to user)
```

**Hive box schema per item:**

```dart
{
  "id": "uuid",
  "photo_path": "/absolute/path/photo.jpg",
  "audio_path": "/absolute/path/audio.m4a",
  "language": "te",
  "created_at": "ISO8601",
  "status": "queued",       // queued | uploading | failed | dead
  "retry_count": 0,
  "last_error": null
}
```

Rules: FIFO · unique IDs · max 3 retries · files preserved until SUCCESS then deleted · UPLOADING resets to QUEUED on app restart.

## TH-13. Connectivity Behavior

Connectivity ≠ internet access. Correct pattern:

1. `connectivity_plus` signals `Connected`
2. App attempts HTTP upload to backend
3. If HTTP **succeeds** → mark `SUCCESS`, delete local files
4. If HTTP **fails** → keep `QUEUED`, increment `retry_count`

Never crash on connection loss. All network calls wrapped in `try/catch`.

## TH-24. Performance Budget

**Target:** `POST /api/v1/listings/process` completes in ≤ 25 s under normal demo conditions.

| Stage | Budget | Action if over |
|---|---|---|
| Validation + temp write | < 1 s | — |
| Whisper STT | < 8 s | Switch `WHISPER_MODEL=tiny` |
| Qwen-Image-Edit | < 10 s | Skip; use original image |
| MobileNetV3 | < 2 s | — |
| Nemotron LLM | < 8 s | Reduce `max_tokens=256` |
| SerpApi | < 3 s | Skip to cost-plus |
| **Total (typical)** | **≤ 25 s** | — |

Measure each stage with `time.perf_counter()`, log `duration_ms`. Tune slowest stages after first end-to-end run.

**Important performance caveats:**
- ≤ 25 s is the target under **normal demo conditions** — it is not an absolute guarantee.
- External API latency (NVIDIA NIM, SerpApi, Google Cloud) is variable and outside the application's control.
- The Flutter Processing screen must animate and wait safely for the actual backend response. **Do not hard-timeout the UI at 25 seconds.**
- Non-critical services (image editing, category, pricing) must degrade gracefully rather than extending total pipeline time.
- Do not display fake progress percentages. Show the 4 defined processing steps (understanding voice, enhancing photo, identifying craft, creating listing) with real state updates.
